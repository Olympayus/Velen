基于开源 Pi Agent 的模块化网络安全审计智能体设计与实现

毕业设计总体方案（指导性版本）

# 一、选题定位与总体思路

本课题面向信息安全工作者的日常审计需求，基于开源 Pi Agent 扩展开发一个模块化网络安全审计智能体。系统不从零开发大模型或重新实现漏洞扫描器，而是利用现有 Agent 框架与成熟安全工具，重点完成任务组织、工具调用、结果整理、报告生成和技能扩展。

第一版以本地代码项目的安全审计为主要应用场景，优先集成代码静态分析与依赖漏洞检查两类工具。项目定位为可运行、可测试、可扩展的毕业设计原型，不以功能覆盖所有网络安全领域为目标。

# 二、研究目标

·    完成基于 Pi Agent 的网络安全审计智能体原型，能够接收自然语言任务并组织多步骤审计流程。

·    集成至少一种代码静态分析工具和一种依赖漏洞检查工具，统一处理工具输出并生成结构化报告。

·    实现简明的技能/工具扩展接口，支持后续通过增加模块扩展至日志研判、授权测试等安全场景。

·    探索预先明确任务范围后的连续执行策略，减少普通审计步骤中不必要的人工介入，并对执行轨迹和关键结果留痕。

·    通过可重复的功能测试和对照实验，评价系统的基本可用性、执行效率与结果质量。

# 三、第一版功能范围

| **模块**       | **第一版内容**                                 | **范围控制**                               |
| -------------- | ---------------------------------------------- | ------------------------------------------ |
| Agent 任务执行 | 接收任务、制定步骤、连续调用工具、跟踪执行状态 | 沿用 Pi Agent，不自研通用  Agent 框架      |
| 安全工具集成   | 代码静态分析、依赖漏洞检查                     | 优先使用成熟工具，不开发自有扫描引擎       |
| 结果处理       | 统一结果格式、风险摘要、证据与修复建议         | 报告需引用工具结果，避免无证据断言         |
| 技能扩展       | 以独立技能描述工作流，以适配器调用工具         | 新增能力尽量不改动核心执行逻辑             |
| 执行记录       | 记录任务步骤、工具状态、错误和输出摘要         | 保留必要的可追溯信息，避免收集无关敏感数据 |

# 四、总体技术路线

1. 需求梳理：确定第一版的输入、输出、运行环境和明确不包含的功能。
2. 框架扩展：使用 Pi Agent 的扩展/自定义工具机制接入安全工具，完成最小可运行闭环。
3. 工作流实现：让 Agent 依次执行代码审计、依赖检查、结果归一化和报告生成；对失败步骤设置有限重试与明确失败提示。
4. 结果验证：保留原始工具输出及必要证据，对报告中的关键结论进行核对。
5. 测试与评估：选取本地开源或自建测试项目，执行固定任务并记录结果，完成分析与论文撰写。

# 五、实施原则与边界

·    范围优先：首先保证“输入任务—执行工具—整理结果—生成报告”全流程稳定，再增加新技能。

·    自主执行：在本地项目或已授权测试范围内，普通读取、分析与既定检查步骤可连续执行；超出已确认范围或可能造成重大影响的操作应重新确认。

·    安全边界：不把提示词作为唯一的权限控制手段；工具适配层应校验路径、目标和参数，并在条件允许时使用受限运行环境。

·    结果可信：区分工具发现、Agent 推断和待人工确认的结论；报告应记录依据，不将“扫描未发现”描述成“系统绝对安全”。

·    时间管理：不把独立前端、复杂数据库、多智能体协作、模型训练和自动化高影响操作列为第一版必做内容。

# 六、测试与评价方案

测试应在本地项目、自建实验环境或明确授权的对象上进行。建议准备包含已知问题与正常样例的固定测试集，以便重复运行和比较。

·    功能正确性：工具能否正常启动、输出能否解析、报告是否完整。

·    任务完成率：预定步骤完成比例，以及任务是否需要人工介入。

·    调用可靠性：工具调用成功率、错误恢复情况和重复调用情况。

·    结果质量：关键发现与原始工具证据的一致性、重复项处理和风险描述准确性。

·    执行效率：总耗时、人工干预次数；可对比直接运行工具、原始 Agent 流程和加入工作流管理后的版本。

# 七、阶段安排（按实际剩余工期调整）

| **阶段**                 | **主要工作**                             | **阶段交付**                    |
| ------------------------ | ---------------------------------------- | ------------------------------- |
| 阶段一：准备与最小原型   | 熟悉 Pi 扩展机制，确定工具与测试项目     | 至少一个安全工具可由 Agent 调用 |
| 阶段二：核心功能实现     | 接入第二类工具、统一结果、生成报告       | 完成端到端审计闭环              |

| 阶段四：测试、论文与答辩 | 固定测试集、对照实验、整理图表和说明文档 | 可演示版本、实验记录、毕业论文  |

# 八、预期成果

·    一套基于开源 Pi Agent 的可运行网络安全审计智能体原型及源代码。

·    至少一条完整的代码与依赖安全审计工作流、可扩展技能/工具接口和报告模板。

·    测试用例、实验记录、结果分析及系统使用说明。

·    本科毕业论文（设计）及答辩演示材料。

# 九、可选扩展方向（不作为第一版交付前提）

在核心版本稳定且时间允许后，可逐步增加安全日志分析、威胁情报关联、授权靶场 Web 安全测试、修复后复测或历史任务对比。每次只增加一个具有明确输入输出和测试标准的技能模块，避免因扩展范围过大影响按期交付。

# 十、风险与应对

·    Agent 调用不稳定：先确保底层工具可独立运行，再通过固定参数和结构化输出接入；失败时保留原始错误。

·    模型分析不准确：以扫描工具原始结果作为证据来源，关键结论进行校验，报告注明不确定性。

·    工期超出预期：保留代码与依赖审计这一条主流程，推迟可视化、更多安全领域和复杂自动化。

·    权限和目标范围不清：第一版限制在本地或授权测试项目中，明确指定可操作目录与目标，避免无边界执行。
